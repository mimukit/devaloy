# QA: the T3 Code server on devaloy

_Not run yet. This covers Phases 1 to 3 of [`docs/plans/0010-plan-t3code-server-2026-10-09.md`](../plans/0010-plan-t3code-server-2026-10-09.md), grilled 2026-10-09._

## Preconditions

- A devaloy host where you can run `docker compose` in the repo checkout.
- This branch is checked out on the host, and the image is built from it.
- A laptop with Tailscale and the T3 Code desktop app.
- A phone with the Tailscale app and the T3 Code app from the store.
- Laptop, phone and box are in the same tailnet.
- `claude` and `codex` are logged in on the box.

In the steps, `<ip>` is the box's tailnet IPv4. Get it with `docker compose exec devaloy tailscale ip -4`.

The process checks run `pgrep` through `docker compose exec`, which uses no shell inside the container. The pattern is the same as `T3_SERVE_PATTERN` in `lib/common.sh`, so it matches the native server and not its `su` wrapper, the `node .../t3.js` launcher, the `t3 acp-mcp-bridge` children, or the command that runs the check.

## 1. Install behind the key (Phase 1)

1. Set `WITH_T3CODE=true` in `.env`.
2. Run `docker compose up -d --build`. The build is for this branch only, not for the key.
3. Run `docker compose logs devaloy | grep -i "toolset"`.
   - Expect: a new toolset hash is installed.
4. Run `ssh devaloy 't3 --version'`.
   - Expect: a version number, for example `0.0.45`.
5. Run `ssh devaloy 'cat /opt/devaloy/runtime-flags'`.
   - Expect: a line `WITH_T3CODE=true`.
6. Run `ssh devaloy 'ls ~/.config/mise/conf.d/'`.
   - Expect: `t3code.toml` is in the list.

## 2. Start the server (Phase 2)

1. Run `docker compose logs devaloy | grep -A4 "T3 Code"`.
   - Expect: `T3 Code server on http://<ip>:3773`.
   - Expect: the server's own output with a pairing URL `http://<ip>:3773/pair#token=...` and a QR code.
2. Run `docker compose exec devaloy pgrep -af '^[^ ]*/t3 serve( |$)'`.
   - Expect: exactly one line, `<path>/@t3code/t3-linux-x64/t3 serve --host <ip> --port 3773 --no-browser`.
   - Record the exact command line here: ______
   - If there is no line, run `docker compose exec devaloy pgrep -af "t3 serve"` and record what it shows. The pattern in `lib/common.sh` then needs a fix.
3. Run `ssh devaloy 'readlink ~/.t3/worktrees'`.
   - Expect: `/home/dev/worktrees`.
4. Run `docker compose exec devaloy pgrep -f '^[^ ]*/t3 serve( |$)'` to get the server PID. Then run `docker compose exec devaloy sh -c 'tr "\0" "\n" < /proc/<pid>/environ | grep T3CODE'`.
   - Expect: `T3CODE_TELEMETRY_ENABLED=false` and `T3CODE_SERVER_BROWSER_SANDBOX=0`.

## 3. Pair the laptop

1. Copy the pairing URL from step 2.1.
2. In the desktop app, open **Settings → Connections → Add environment**.
3. Paste the URL and connect.
   - Expect: the box appears as an environment.
4. Start a Claude Code thread in a repo on the box. Ask it to run `hostname`.
   - Expect: the box's hostname, not the laptop's.
5. Start a Codex thread and ask the same thing.
   - Expect: the box's hostname.

## 4. Pair the phone

1. Turn off Wi-Fi on the phone. Use cellular data. Keep Tailscale connected.
2. On the laptop, run `ssh devaloy t3 pair`.
   - Expect: a link that starts with `http://<ip>:3773/`, not `127.0.0.1`.
   - Expect: a QR code.
3. In the phone app, open **Settings → Environments → Add environment**. Scan the QR code.
   - Expect: the box appears as an environment.
4. Open the Claude Code thread from step 3.4.
   - Expect: the thread and its messages show on the phone.

## 5. Laptop asleep

1. On the phone, send a long task to the Claude Code thread, for example "count the lines in every file in this repo, one file at a time".
2. Close the laptop lid.
3. Watch the thread on the phone for two minutes.
   - Expect: the thread keeps making progress.
4. Open the laptop.
   - Expect: the desktop app reconnects and shows the same progress.

## 6. Restart and isolation

1. Run `docker compose exec devaloy pkill -f '^[^ ]*/t3 serve( |$)'`.
2. Wait 15 seconds. Run `docker compose exec devaloy pgrep -af '^[^ ]*/t3 serve( |$)'`.
   - Expect: a new server process with a different PID.
3. Look at both apps.
   - Expect: both reconnect without a new pairing link.
4. On the Docker host, get the container's bridge IP: `docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' $(docker compose ps -q devaloy)`.
5. On the Docker host, run `curl -m 5 http://<bridge-ip>:3773/`.
   - Expect: the connection fails.
6. From the laptop, run `curl -s -o /dev/null -w '%{http_code}\n' http://devaloy:3773/`.
   - Expect: an HTTP status code, which proves the MagicDNS name reaches the server.

## 7. Browser tab

1. In the desktop app, open a browser tab in a thread on the box. Load `https://example.com`.
2. Record the result here: works / fails with ______.
   - If it fails, run `docker compose logs devaloy | grep -i browser` and record the error.
   - Either result passes this step. The server must still be running after it.

## 8. Doctor, status and ram (Phase 3)

1. Run `ssh devaloy devaloy doctor`.
   - Expect: `t3 server` is `ok` and `t3 cli` is `ok`.
2. Run `ssh devaloy devaloy status`.
   - Expect: a `t3` line that says `up, N MiB across M process(es)`.
3. Run `ssh devaloy devaloy ram --t3`.
   - Expect: the T3 Code server memory and a warning that a restart cancels running turns.
   - Expect: `would restart the T3 Code server (--apply to do it)`.
4. Run `ssh devaloy 'devaloy ram --t3 --apply'`.
   - Expect: `T3 Code server back up after Ns`, with N at 40 or less.
   - Expect: both apps reconnect.
5. Run `ssh devaloy 'devaloy ram'` with no flags.
   - Expect: no T3 Code section in the report. The T3 Code restart runs only with `--t3`.
6. Run `ssh devaloy devaloy`, open the ram view, and look at the rows.
   - Expect: no `t3 server tree` row.
7. Run `docker compose exec devaloy pkill -f '^[^ ]*/t3 serve( |$)'`. Then run `ssh devaloy devaloy doctor` within 10 seconds, before the loop restarts the server.
   - Expect: `t3 server` is `broken`, and the exit code is 1.
   - The loop restarts the server after 10 seconds. Run `devaloy doctor` again to see `ok`.

## 9. The worktree root

1. In the desktop app, start a thread in a new worktree.
2. Run `ssh devaloy 'ls ~/worktrees'`.
   - Expect: the new worktree is in the list.

## 10. Turn it off

1. Set `WITH_T3CODE=false` in `.env`. Run `docker compose up -d`.
2. Run `docker compose exec devaloy pgrep -af '^[^ ]*/t3 serve( |$)'`.
   - Expect: no output.
3. Run `ssh devaloy devaloy doctor`.
   - Expect: `t3 server` is `off`, and there is no `t3 cli` row.
4. Run `ssh devaloy devaloy update`.
5. Run `ssh devaloy 'command -v t3'`.
   - Expect: no output.
6. Run `ssh devaloy 'ls ~/.t3/userdata/statev2.sqlite'`.
   - Expect: the file is still there.
